## 2. 输入契约与可信度

| 字段 | 含义 | 允许用途 |
|---|---|---|
| `{input.user_query}` | 用户本轮问题 | 识别真正意图 |
| `{input.context}` | 已确认的会话或任务上下文 | 消歧、继承已确认参数 |
| `{input.candidates}` | 真实候选任务/API/选项 | 只能从中选择真实 ID |
| `{input.evidence}` | 本轮可用证据 | 提取可核验事实，不得扩写 |
| `{input.constraints}` | 当前任务限定 | 检查优先级、范围、权限 |

只引用输入实际存在的字段。**没有给出的数据视为未知，不能靠常识、示例或猜测补齐。** 如某字段在实际业务中不存在，删除该行并更新判定规则。

## 5. 字段生成规则

- `{output.field_1}`：{取值范围、来源、是否允许空值}。
- `{output.field_2}`：{只取本轮新信息 / 是否允许继承旧值}。
- `{output.field_3}`：{如何处理真实候选 ID、引用、时间、缺项}。
- `{output.question}`：仅在 `{需要澄清的状态}` 时填写；长度 ≤ `{最大字数}`，只问一个明确问题，不使用内部技术词。
- `{output.missing_information}`：只记录真正缺少的信息，不把未证实内容写成已知事实。

需要区划、文件效力、指标口径、引用等**专项规则**时，在此增加最少量且可执行的判定条件；不要复制整个知识库手册。

## 6. 输出契约

> 下列是**示意结构**。实现时必须用你所在系统的真实字段名、字段类型、枚举和空值规则替换；不要把示意键直接当作生产接口契约。

```json
{
  "status": "{状态A}",
  "result": "{已核实的输出内容}",
  "selected_id": "{真实候选ID或空字符串}",
  "missing_information": [],
  "reason_code": "{既定原因码}"
}
```

**序列化要求：**
- JSON 模式只输出一个合法 JSON 对象；不用 Markdown 围栏、注释或多余前后缀。
- 固定字段必须全部出现，字段类型、空数组、空字符串按接口契约填写。
- 只能使用来源中真实存在的 ID、marker 和数据值。
- 若是非 JSON 文本模块，删除上述示例并明确文本结构、引用格式和字数要求。
