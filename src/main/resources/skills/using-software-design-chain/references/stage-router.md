# 阶段与工作项路由

任何路由先检查铁律：候选是否已发现并保留证据、是否已追加为 `00-control/work-item-registry.csv` 真实数据行、是否在阶段主清单CSV存在同ID/引用行、作为正式输入的项目是否已逐项确认并回写确认状态/证据。只在回复或Markdown声称登记、只返回ID、CSV仅有表头均视为未登记。缺一步就只路由回该步骤，不启动正式下游设计。

## 连续路由

路由一个工作项是并发控制，不是终止点。工作项关闭后按顺序执行：选择同一清单下一个已登记未确认项；清单闭合则运行 `STAGE_CLOSURE`；阶段通过则进入下一阶段。除G7、请求范围完成、真实人工阻塞或无法自修复失败外，始终返回 `continuation_required=true` 并立即继续，不向用户逐项询问是否继续。

## GF前置守卫

检测到代码、构建文件、源码、DDL/迁移或上传工程ZIP时设置 `codebase_status=EXISTS`。若同一代码版本没有GF通过证据，下一路由无条件为“总入口创建专用只读子代理，并在任务中显式要求使用 `inspect-existing-project-capabilities`”。进入领域映射、数据、后端或前端前再次检查GF产物、代码版本和 `project_probe` 执行记录。仅在明确 `GREENFIELD` 时允许无复用目录继续。

子代理可用时只有探查任务已追加到 `work-item-registry.csv` 与 `project-foundation/probe-task-register.csv`，并具备 `execution_mode=SUBAGENT`、非空 `agent_task_ref`、指定技能名、同版本产物引用和 `status=PASSED`，才算完成探查；任务创建但未返回仍为进行中。仅环境不支持子代理时可登记 `PARENT_FALLBACK` 及原因。隐式技能匹配、主代理自行扫描后补写子代理字段、无任务引用的口头说明均不得通过GF。

## 判定顺序

1. 显式点名技能：使用该技能并验证上游。
2. 从方案到完整设计或继续整链：使用总入口。
3. 只要表/API/页面/测试：使用对应阶段；无AI基线清单时先运行 `PLAN`。
4. 写代码/修复：设计切片已基线化并通过增量审查后退出本链进入实施；否则只补必要设计。

## 路由

| 当前情况 | 下一动作 |
|---|---|
| 无来源/项目/切片 | 需求精炼/G0 |
| 范围、术语、需求未基线化 | 需求精炼/G1 |
| 场景、规则、状态、权限不闭环 | 场景规则/G2 |
| 有存量代码但未探查 | 总入口创建只读子代理 → 子代理显式使用项目能力探查/GF |
| 边界、聚合、不变式不明确 | 领域边界/G3 |
| 无数据候选清单 | 数据模型 `PLAN/DM0` |
| 有清单未闭合 | 选择一个数据工作项继续DM1—DM4 |
| 无用例/页面/测试清单 | 对应阶段 `PLAN` |
| 有清单未闭合 | 选择一个工作项逐项设计与验证 |
| 工作项刚BASELINED/变化 | 自动执行一致性 `INCREMENTAL` |
| 阶段清单已闭合 | 一致性 `STAGE_CLOSURE` |
| 全阶段闭合 | 一致性 `FINAL_G7` |

GF可在G1后与G2并行，但存在代码库时，G3正式映射和G4详细设计不得绕过GF。绿色项目也登记一次探查结果。

## 第4阶段后的调度

候选清单可全局发现；详细内容不可全局生成。数据模型一次只设计一张表，后端一次一个用例，前端一次一个任务/页面，测试一次一个覆盖义务。每次开始前重新读取该项的文档定位、上游ID、已基线化相邻项、现有组件/表/API、架构剖面和决策。

优先按纵向切片收敛：数据工作项基线化并自动增量审查后设计依赖它的用例/API，再设计页面和测试；不要求整库设计完才开始首个业务切片，但跨表/跨用例依赖必须明确。

## 状态处理

- `READY`：登记产物、清单闭合和Gate证据；
- `READY_WITH_ASSUMPTIONS`：仅允许不依赖假设的候选工作；
- `NEEDS_CONTEXT/BLOCKED`：报告工作项、阻塞ID、影响和责任人；
- `REVISE_UPSTREAM`：只重开变化ID可达的工作项；
- `FAILED_VALIDATION`：保留候选和日志，原项修复后重验。

## 基线与合并

计划和工作项共享项目、切片、业务基线、代码版本、术语、问题/决策和追踪账本。以稳定ID和版本为冲突键；发现输入漂移、同一ID不同语义或两个 `RESEARCHING` 时停止合并并裁决。

G4由DATA和BACKEND两个组件组成。进入详细前端合同和G5前，两组件在相关纵向切片必须通过；不要求无关切片提前完成。

失败产物不得登记为已基线化；重试引用同一问题ID、工作项和输入版本。若根因来自上游，返回目标阶段和关闭条件。能由AI修复的问题自动路由；只有满足总入口三项人工介入条件时才请求用户。
