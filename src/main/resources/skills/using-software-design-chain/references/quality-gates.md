# GF与G0-G7质量门

铁律适用于所有Gate：存在“已发现但未追加到 `work-item-registry.csv` 和阶段主清单CSV”“只在回复/Markdown声称登记”“只返回 `registered_ids`”“CSV仅有表头”“已登记未回写逐项确认却进入正式下游”或批量生成后补登记的情况，对应Gate直接 `FAILED`，不能以人工未审查为由，也不能用文件存在或格式校验豁免。

连续执行同属铁律：有已登记未确认项或后续阶段可运行时却无允许的 `stop_reason` 而停止，阶段状态不得标记READY/完成。检测到代码却未显式执行GF，G3及其后Gate直接失败。

| Gate | 阻塞条件 |
|---|---|
| G0 来源 | 来源/版本/所有者/权威、项目代码、切片、目标或排除范围未知 |
| G1 需求 | 重大范围冲突未决；Must/NFR无验收意图；角色/术语不可判定 |
| G2 行为 | 核心能力无主/异常流程；规则无例外；状态无守卫；权限无数据/字段维度 |
| GF 工程事实 | 代码版本/范围未知；探查任务未追加到全局及阶段CSV；子代理可用却未由总入口实际创建专用只读任务；子代理任务未显式点名 `inspect-existing-project-capabilities`；`project_probe` 缺任务引用/同版本产物/合格返回；不满足条件却使用主代理降级；探查无证据合并；架构形态/依赖方向未知；关键基础能力无证据；`NEW/REPLACE/UNKNOWN`未闭环 |
| G3 边界 | 数据多写入者；聚合无不变式；事务/失败恢复未知；旧模块/表直接决定边界 |
| G4 可实现 | DM0清单或工作项未AI基线化/检查；表/用例清单未闭合；包映射违背现有架构；物理规范违反；写用例无权限、事务、并发、幂等、错误、审计或复用决策 |
| G5 前后端 | 页面工作项未闭合；页面动作无用例/API；字段/枚举漂移；异常、冲突、超时或时间戳未设计 |
| G6 验收 | 覆盖义务清单未闭合；Must/NFR、规则、状态、权限、契约、迁移或基础组件适配无验证 |
| G7 全链 | 增量审查未闭合；存在BLOCKER/CRITICAL、无效豁免、重复基础建设、孤儿/漂移产物 |

严重度：`BLOCKER CRITICAL MAJOR MINOR`。BLOCKER/CRITICAL必须闭环；MAJOR仅凭带责任人、理由、期限和决策ID的豁免通过；MINOR进入修订队列。

单个工作项通过不等于阶段Gate通过。Gate报告必须包含发现/登记/确认/未确认数量、清单总数、已基线化/一致性检查/验证/阻塞/剩余数量、输入版本、检查结果和证据。人工阶段审查是可选反馈渠道，不是逐项Gate；结构检查或目录齐全不能提升Gate。
